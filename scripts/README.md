# scripts/ — repo-level Node scripts

Plain Node ES modules (`.mjs`, no dependencies beyond the workspace root's dev
dependencies — the asset pipeline decodes PNG sources with `pngjs` — no shell features) so they run the same from bash, cmd.exe and PowerShell.

| Script | Run with | Purpose |
|---|---|---|
| [`frame.mjs`](frame.mjs) | imported by the scripts (the apps' too: `apps/webos/scripts/appinfo.mjs`), `test/e2e/frame-pixels.ts` and `test/e2e/playwright.config.ts` | v2 R1-02: the game's frame constants (`FRAME_W` / `FRAME_H`, the HUD bars, the playfield, `TILE_SIZE`, the font metrics) and `WORLD_SCALE` (R2-02) as a plain-JS mirror of `@shmup/core`'s, plus `SPAWN_LEAD` (`DEFAULT_SPAWN_SCREEN_X` = `PLAYFIELD_W + 16 · WORLD_SCALE`) and `CAPTURE_SCALE` (`floor(1280 / FRAME_W)`, the e2e and docs capture scale); `test/scripts/frame.test.ts` pins every export to core, and the repo-wide frame-literal scan (`test/integration/frame-literals-repo.test.ts`) sends every Node script here for its frame numbers |
| [`clean.mjs`](clean.mjs) | `pnpm clean` (and every package's `clean` script) | Cross-platform `rm -rf` for build output; refuses paths outside the cwd and `node_modules` |
| [`generate-assets.mjs`](generate-assets.mjs) | `pnpm assets` (Turborepo `//#assets`, before every `build` / `dev`; `--force`, `--out DIR`, `--source DIR`, `--quiet`) | Placeholder asset pipeline: sprite pixel maps + procedural generators + real-art PNG overrides + bitmap fonts → `assets/generated/atlas/main.png` (+ `main-1.png` …) and `main.json`; since R1-05 packed by group (`main.png` = `common`, then one page per zone, from `assets/source/atlas-groups.json`) and written as lossless PNG-8 where a page fits 256 colours; input-hash cache skips unchanged runs; exit 1 lists invalid sources |
| [`assets/`](assets/) | imported by `generate-assets.mjs` and the `shmupAssets()` Vite plugin | The pipeline's modules: `png.mjs` (zero-dependency encoder — since R1-05 also lossless indexed PNG-8 with `{ indexed: 'auto' }`, which only the atlas opts into —, pngjs decoder), `image.mjs`, `rng.mjs`, `sprite-source.mjs` (`*.sprite.json`, PNG + Aseprite sidecar overrides — the sidecar's pivot wins over a code anchor, the ingest tool's `*.recipe.json` / `*.art.json` / `*.edit.png` are skipped, R3-02), `procedural/*.mjs` (seeded generators; `terrain.mjs` draws any tile size and resamples masks, R1-04), `flash.mjs` (`@flash` silhouettes), `font.mjs`, `packer.mjs` (MaxRects, ≤ 2048² pages; R1-05: one set of pages per `group`, `groupOrder`), `manifest.mjs` (format 2 since R1-05: `pages[].group`), `pipeline.mjs` (orchestration + cache; R1-05: `loadAtlasGroups` / `resolveAtlasGroup` — the groups file by base name, then a `zone-<id>` directory, else `common` — and `buildAtlas({ ungrouped: true })`, the one-page layout the TV bench and the CJK figures use), `standin.mjs` (R3-04, decision W5-14: the stand-in art kit — `standinZone` builds one zone's palette / far layer / keyed bands / tile set in memory per the art bible, `standinAtlas()` packs all nine stand-in zones with the real pipeline into the `standin-zone-<x>` groups — what `test/integration/standin-budget.test.ts` and the TV bench's decode pages (`apps/tizen/scripts/bench-decode.mjs`) build from) |
| [`assets/interim.mjs`](assets/interim.mjs) | imported by `assets/pipeline.mjs` and `assets/procedural/lasers.mjs` (and by tests that read the packed atlas: the asset tests, `integration/cjk-budget.test.ts`, `integration/dimension-runtime.test.ts` and `integration/raster-range-runtime.test.ts`) | v2 R2-01, the interim art stage (decisions W4-4 / W4-5): `INTERIM_ART_SCALE` (1 until R2-01's flip, then 3/2 — a mirror of core's `ART_SCALE`, pinned by `test/scripts/assets/terrain-size.test.ts`) and the exact-fraction scalers `parseArtScale`, `scaleLength`, `scaleImage` (nearest-neighbour: `⌈s·w⌉ × ⌈s·h⌉`, source pixel `⌊d / s⌋`), `scaleAnchor` (`⌈s·a⌉`), `scaleSprite` and `scaleFont` (the 6×8 font → a 9×12 cell, a 15-px line, a 9-px advance). `buildAtlas({ artScale })` / `collectSprites({ artScale })` (default `INTERIM_ART_SCALE`) scale every v1-scale source before the PNG overrides and never scale the terrain tilesets (drawn at `TILE_SIZE · artScale / INTERIM_ART_SCALE`), `ui/pixel`, the laser beams and their `@<palette>` variants (the renderer reads a beam frame's number as its thickness, so `lasers.mjs` draws them at the art scale through the generators' `artScale` option: frame `k` a band `k + 1` px tall, 8 frames of 4×8 at 1, 12 of 6×12 at 3/2), PNG overrides or a `native` source (a pixel map's `"native": true` key, `makeSprite({ native })`); `artScale: 1` is the v1 art at either frame — what the TV bench atlas, the CJK figures, the store icons and the doc images build from (W4-6); `generateAssets` always builds the default scale |
| [`audio-preview.mjs`](audio-preview.mjs) | `pnpm audio:preview` (`--out DIR`, `--only NAME`, `--quiet`) | Renders every placeholder SFX cue and chip song of `content/audio/` to 16-bit mono WAV files in `assets/generated/audio-preview/` (a looping song as intro + loop + loop, so the seam can be heard), printing each file's `pcmHash` and a song's loop points; loads `@shmup/audio-web`'s TypeScript through Vite's `ssrLoadModule` |
| [`gen-trig-tables.mjs`](gen-trig-tables.mjs) | `pnpm trig:tables` (`--check` to verify, `--out FILE` to write elsewhere) | Regenerates the committed `packages/core/src/math/trig-table.ts`; computed with BigInt fixed-point maths so the output is byte-identical on every engine (`packages/core/test/math/trig-table.test.ts` enforces it) |
| [`content/tiled-import.mjs`](content/tiled-import.mjs) | `pnpm content:tiled <map.tmj>` (`--id ID`, `--stages DIR`, `--paths DIR`, `--print`) | Converts a Tiled JSON map (M2-07) into stage content: the tile layer → `tilemap.rle` rows, object-layer entities → timeline events at their scroll x (spawns 400 px ahead of their object), camera keys, checkpoints, region triggers, moving blocks and branches, polylines → a `paths` file; writes `content/stages/<id>.stage.json` (+ `content/paths/<id>.paths.json`). `test/scripts/content/` converts the committed fixture map and compares it with the expected JSON |
| [`content/rescale.mjs`](content/rescale.mjs) | `node scripts/content/rescale.mjs --factor K [--top-pad P] [--dry-run]` (`--root DIR`, `--no-examples`, `--from-width W`, `--from-height H`, `--tile-size T`, `--to-width W`, `--atlas FILE`, `--art-scale S`, `--force-art-scale`, `--json`, `--quiet`) | v2 R1-03: ports `content/` to a new world scale by the **unit** of every number (core's and the other packages' file schemas, loaded through Vite's `ssrLoadModule`): world values ×k, absolute y + the top pad, edge-anchored values snapped, field pairs, the backdrop and the map's right end together; rewrites only the changed numbers, formats with Prettier, lists what a port must check by hand and refuses to write while anything is unclassified. The real ×1.5 run **ran** — R2-02's port (`8dbe858`); since the port, `--factor 1 --dry-run` is the identity check on the shipped content — see [`content/README.md`](../content/README.md#units) and [`docs/dev/content-data.md`](../docs/dev/content-data.md#units-and-the-rescale-tool-r1-03) |
| [`store-assets.mjs`](store-assets.mjs) | `pnpm store:assets` (`--check` to verify the committed icons, `--out DIR` for the store folder) | The icon set and the store-listing placeholders (M2-18) drawn from the placeholder art with integer scaling only: the committed `apps/tizen/public/icon.png` (512 × 423) and `apps/electron/build/icon.png` (512 × 512), and `assets/generated/store/` — the icon, four 1920 × 1080 placeholder screenshots and `listing.json`; `test/scripts/store-assets.test.ts` compares the committed icons' pixels with a fresh rendering ([`docs/dev/release-hardening.md`](../docs/dev/release-hardening.md#icons-and-store-listing-placeholders)) |
| [`itch-package.mjs`](itch-package.mjs) | `pnpm itch:package` (`--dist DIR`, `--out FILE`) | M3-03: packs the browser build (`apps/web/dist`) into the ZIP itch.io's HTML5 hosting wants — `index.html` at the archive root, source maps left out — with a zero-dependency ZIP writer (deflate + CRC from `node:zlib`, fixed timestamps), so the same build always produces a byte-identical archive. **Never run against a real build here, and nothing has been uploaded** ([`docs/client/web-release.md`](../docs/client/web-release.md)) |
| [`golden-update.mjs`](golden-update.mjs) | `pnpm golden:update` | Re-blesses the golden replays (M1-19): runs Vitest on `test/golden` with `SHMUP_GOLDEN_UPDATE=1` (set by the script, so it works in cmd.exe too), which re-records every scenario from its bot, rewrites `test/golden/*.replay.json` and checks the new files. Only for an intended simulation change — say why in the commit message ([`docs/dev/debug-and-replays.md`](../docs/dev/debug-and-replays.md#golden-replays-testgolden)) |
| [`doc-images.mjs`](doc-images.mjs) | `pnpm docs:images` (`--check` to verify the committed pictures, `--quiet`) | The pictures the player docs show, drawn from the same sources as the game: the README's logo banner (the `ui/logo` sprite over its own star bands and the pixel font), one plate per `enemies/`, `shots/`, `items/`, `options/`, `shields/` and `ships/` sprite through `collectSprites`, and one portrait per boss **assembled from its `content/enemies/*.enemies.json` part tree** (parents first, cores last, trimmed and scaled to fit). Output: `docs/images/` — committed, so the docs render without the asset pipeline ([`docs/client/bestiary.md`](../docs/client/bestiary.md), [`docs/client/arsenal.md`](../docs/client/arsenal.md)) |
| [`doc-screenshots.mjs`](doc-screenshots.mjs) | `pnpm docs:screens` (`--only a,b`, `--quiet`) | The docs' screenshots, captured from the **real game**: it serves `apps/web/dist` (build it first with `pnpm turbo run build:test --filter=@shmup/web`), drives the menus in headless Chromium, freezes the sim with the debug tools' frame advance and steps to an exact tick before screenshotting the canvas at the e2e capture scale (×2) — so the same tick always gives the same picture. Output: `docs/images/screens/` (the title, the menus, every zone, the WARNING, a boss, the tally and the ZONE MAP) |
| [`art-origins.mjs`](art-origins.mjs) | `node scripts/art-origins.mjs` (`--check`, `--list`, `--json`; `--source DIR`, `--staging DIR`, `--models FILE`) — no `pnpm` script; CI runs it through `test/scripts/art-origins.test.ts` | v2 R3-05 part 2, the origin report: every sprite the atlas packs by origin (procedural / hand / ai-assisted) and kind, with the served model of every source and edit reference, read from `collectSprites()`, the override PNGs' `.art.json` records (checked with the ingest tool's `art-prompts/ingest/lib/provenance.mjs`) and `art-prompts/ingest/models.json`; `--check` exits 1 on an untraced override, a model or licence that is not the table's, a `hold` verdict anywhere in a record's source tree, an unreviewed AI record, a `reference` without real cleanup or a path into the candidates folder (in the staging folder `art-prompts/v2/ingested/` a hold, a missing review and a light reference only warn) — [`docs/dev/art-provenance.md`](../docs/dev/art-provenance.md#9-part-2-the-origin-report) |
| [`assets/tileset-masks.mjs`](assets/tileset-masks.mjs) | `node scripts/assets/tileset-masks.mjs --check [<tileset>.tileset.json <name>.masks.json]` \| `--write <tileset> <masks.json> [--allow-remap]` (`--root DIR`) — no `pnpm` script; `test/scripts/assets/tileset-masks.test.ts` runs it in-process | v2 R3-03 part V4b, the repo-side mask copy: moves the column-height masks the ingest tool derived from real art (its `<name>.masks.json` sidecar, matched **by frame index**, names only warning) into the designed tileset JSON — text-splicing the `mask` arrays and re-formatting with Prettier, writing only the file it is given. `--write` **refuses** to change a solid tile's mask (the heightfield places those by anchor + mask, decision W5-11) without `--allow-remap`, and writes nothing when it refuses. `--check` is the guard the ingest run cannot be — its own `--check` rewrites the sidecar silently: this one **fails loudly** when a tileset and its sidecar disagree, per pair or as a scan of every sidecar under `assets/source/sprites/` and `art-prompts/v2/ingested/` |
| [`bullet-readability.mjs`](bullet-readability.mjs) | `node scripts/bullet-readability.mjs` (`--out DIR`; default: the git-ignored `assets/generated/readability/`) — no `pnpm` script; `test/scripts/bullet-readability.test.ts` drives it through `--out` into a `mkdtemp` folder | v2 R4-02.B1, the bullet readability sheets: 36 pictures — every shipped v2 bullet (the three shapes × three families as the enemy pool's worst load of 512, `MAX_ENEMY_BULLETS`) × the 9 campaign zones × the 4 palettes (standard, `@deuteranopia`, `@protanopia`, `@tritanopia`) — each zone's backdrop from the stand-in atlas (`scripts/assets/standin.mjs` `standinZone`: the far layer cropped to one screenful, its first mid band on the bottom edge) under that load, on a full-frame 640×360 sheet (`FRAME_W × FRAME_H` from `scripts/frame.mjs`, no frame literal). `--out` is honored, and the layout is deterministic by `seedOf` (the backdrop's default seed, a fixed shape/family/direction cycle, positions through `createAssetRng`), so two runs are byte-identical; the owner's legibility sign-off reads these sheets (recorded by R4-02.B4) |

App-specific scripts live with their app, e.g. `apps/tizen/scripts/` (bundle check with the size budgets, Tizen
CLI package/install/run wrappers), `apps/webos/scripts/` (M3-03: the `appinfo.json` validator, a bundle check that
imports the Tizen budgets, and the `ares-*` wrappers — **none of the `ares-*` ones has ever been executed**) and
`apps/electron/scripts/` (copy the web build).
Standalone tools with their own dependencies go in `tools/` (outside the pnpm workspace).
