# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `pnpm test`'s unfiltered tail is only Vitest's per-project "Transform |<project>| transforming modules took Ns" advisory — `tail -25` shows six of those and **no** pass/fail line, which reads as a silent failure. Always `grep -E "Test Files|Tests |FAIL"` instead (current baseline: 662 files / 7,972 tests). Same for `pnpm build` → `grep -iE "app.js|gzip|Tizen bundle OK|ERROR"`, and for `pnpm bench` → `grep -E "Test Files|Tests |FAIL|Duration"` plus `grep -E "^\[bench\]"` for the per-scenario lines.
- **[pattern]** The whole gate fits in a few Bash calls if you pass an explicit long `timeout` (900000–1800000) and tail/grep each stage. Current budget: `pnpm install --frozen-lockfile` ~35 ms, `pnpm format:check` ≈ 30 s, `pnpm lint` ≈ 30–80 s (cached/uncached), `pnpm typecheck` ≈ 17–26 s, `pnpm test` ≈ 75 s, `pnpm build` ≈ 18–47 s (0.1 s on FULL TURBO), `pnpm test:e2e` ≈ 3.5 min (259 specs), `pnpm bench` ≈ 3 min (18 tests; the render bench alone ≈ 2 min). Without an explicit timeout the chain dies at the 120 s default and only the first command's output survives.
- **[fix]** `@typescript-eslint/unbound-method` also fires when you *read or reassign a class's method as a value* — hooking a third-party singleton (`const original = TexturePool.createTexture; pool.createTexture = wrapper`) errors in both the source and the test's fake. The fix that works here: declare a local `interface` whose member is a **property with a function type**, cast the class through it (`pool as unknown as PooledTextureFactory`), and build the fake from that interface with an arrow property. Have the fake factory return both shapes (`{ pool, handle, calls }`) so the test calls through `handle` and the code under test takes `pool`.
- **[gotcha]** Do not poll a background Bash task by `until [ -s <its .output file> ]` from *another* background task — the poller's own output file is also empty until it exits, so you end up polling the poller. Poll from a foreground call with a long `timeout` (`until grep -qE "Tasks:|ERROR" <file> 2>/dev/null; do sleep 10; done`), wait on the real process, or use `Monitor` with `tail -f` on a log you redirected yourself. Pick a marker the run really prints — `"Tests "` for `pnpm test`/`pnpm bench`, `"Tasks:|ERROR"` for turbo (`pnpm build`/`pnpm lint`), `"passed|failed|Error"` for `pnpm test:e2e`.
- **[fix]** When a chained `pnpm lint … && pnpm typecheck …` call hits the 120 s timeout and returns *empty* stdout, do not re-run the chain — the harness backgrounds it and keeps going. `Read` the returned `backgroundTaskId`'s `.output` file instead; both stages' turbo summaries are there.
- **[convention]** A plan step's outcome is recorded as an `- **As built:**` block appended directly after that step's `- **Refs:**` line in `shmup_plan.md`, with one nested bullet per area. Beyond "what was left out and why" and "still manual", the strongest blocks also record **where the implementation deviated from the plan's wording and why** and **how a measured number must not be over-read**. Review fixes get their own nested bullet (`(review round 1)` / `- **Review fixes (round 1).** …`) — do not rewrite the original prose.
- **[convention]** A step that supersedes a claim in an existing doc **edits that claim in place** rather than only appending: a finished review finding gets `~~struck through~~` with "**fixed in M3-0x**", its heading gains `· Addressed by M3‑0x`, the report gains an `> **Update (M3-0x).**` block at the top, and a superseded fact is reworded so it does not go stale when a later step moves it again. When a CI job or command gains a prerequisite, add it to **all four** places that describe it: `.github/workflows/ci.yml`, the CI job table and troubleshooting table in `docs/dev/build-test-deploy.md`, the tree line in `docs/dev/repo-layout.md`, and the command block in the feature's own `docs/dev/*.md`.
- **[gotcha]** A backgrounded `pnpm …` task's `.output` file can stay **0 bytes for its whole run** (the harness only flushes when the pipeline ends), so `tail`/`grep` on it tells you nothing about progress and `until [ -s … ]` never fires early. When you need the summary reliably, redirect yourself instead: `(pnpm test > $SCR/full-test.log 2>&1; echo "exit=$?" >> $SCR/full-test.log)` in the background, then poll with `until grep -q "exit=" $SCR/full-test.log; do sleep 15; done` from the foreground with a long `timeout`. The `exit=` sentinel is both the completion marker and the status.
- **[gotcha]** Even a *finished* `pnpm test` background task's `.output` may hold only ~19 lines — Vitest's "Transform |<project>| transforming modules took Ns" advisories and `[exited with code 0]`, with the `Test Files` / `Tests` summary lines missing entirely. `grep -E "Test Files|Tests "` then returns nothing, which looks like a failure. Re-run redirected to your own log file to get the counts; do not conclude the suite failed from an empty grep.
- **[pattern]** `pnpm format:check && pnpm lint && pnpm typecheck` chained in one Bash call exceeds the 120 s foreground timeout unless you pass an explicit long `timeout` (e.g. 900000–1800000) and tail/grep each stage. Current budget: `pnpm format:check` ≈ 30 s, `pnpm lint` ≈ 30–80 s (uncached ≈ 1 m 18 s, 9 turbo tasks), `pnpm typecheck` ≈ 17–31 s, `pnpm test` ≈ 75 s–10 min under load, `pnpm build` ≈ 5–47 s (6 of 9 tasks cached), `pnpm test:e2e` ≈ 3.5 min (259 specs), `pnpm bench` ≈ 3 min.
- **[pattern]** Edit long prose lines in Markdown/plan *and* TypeScript files with a `python3 - <<'PY'` heredoc that asserts the old substring exists before replacing (`assert old in s` / `assert s.count(anchor)==1`) — the anchors are 100-column wrapped sentences that are hard to match exactly with Edit, and the assert turns a silent no-op into a visible failure. Chain `npx prettier --write <file>` and the focused `npx vitest run --project integration <file>` in the *same* Bash call so an edit that breaks formatting or the suite is caught immediately.

- **[convention]** A new browser-side benchmark or harness under `test/bench/` is **not** part of `pnpm test` (its own Vitest config) — but it still needs `test/tsconfig.json` updated to cover the new files, or `pnpm typecheck` skips them silently. Pair it with a headless `test/integration/*.test.ts` that reads the bench sources as text and asserts the claims only a browser run could otherwise verify (`expect(perf).toContain('width: 768, height: 432')`, `expect(main).toContain('countDrawCalls: true')`) — that pulls the bench's invariants into `pnpm test` without launching a browser.
- **[fix]** Do not chain `git fetch && git rebase origin/master && git add …` before staging — the rebase aborts on a dirty working tree (`error: cannot rebase: You have unstaged changes`) and the whole chain returns with nothing done. Stage first (`git add <explicit paths>`), or compare (`git log --oneline origin/master -1` vs `git log --oneline -1`) and skip the rebase when the remote has not moved.
- **[pattern]** Stage a step's files by explicit path, never `git add -A` — list every modified and new file in one `git add … && git status --porcelain` call and read back the `M`/`A` markers to confirm nothing extra (scratch logs, `dist/`, generated atlases) came along.

- **[gotcha]** A python heredoc replace that splices a multi-line block into the middle of a Markdown paragraph leaves the old sentence welded onto the new text's last line (`… wrong **silently**. The page puts the **real**`). After any block insertion, re-read the region (`sed -n 'A,Bp'`) and fix the seam — Prettier does not reflow Markdown prose, so nothing else will catch it.
- **[gotcha]** Relative words in docs ("recorded below", "the sixth line") break as soon as a later edit inserts something between them and their referent. Prefer "this step recorded", "the panel's last line" — and when a count *is* the point, say both forms ("the panel's **seventh** line (row 6, the index the code uses)") so the prose and the constant cannot silently disagree.
- **[pattern]** Check the docs index is complete with a loop instead of by eye: `for f in $(ls docs/client/*.md docs/dev/*.md | sed 's|docs/||'); do grep -q "($f)" docs/README.md || echo "MISSING: $f"; done`. Silence means every doc is linked.
