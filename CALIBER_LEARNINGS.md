# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[env]** `tools/input-probe/` (npm, outside the pnpm workspace) has its own three-program typecheck: `npm run typecheck` runs `tsconfig.json` + `tsconfig.node.json` + `tsconfig.test.json`. After touching anything there run `npm run typecheck`, `npx vitest run` (18 files / 511 tests) and `npm run verify` (vite build → `check-compat.mjs`) — the root gate covers none of it.
- **[convention]** Test counts quoted in `shmup_progress.md` must come from the run that actually passed — write the row with a placeholder and fill it from the green run; a guess is always wrong ("33 new (8,316)" was really 39 / 8,050). Current baselines: root suite **8,098 tests**, 266 e2e specs, shell project 63 files / 457 tests, `tools/input-probe` 18 files / 511 tests.
- **[pattern]** The whole gate fits in a few Bash calls if you pass an explicit long `timeout` (900000–1800000) and grep each stage; without one the chain dies at the 120 s default and only the first command's output survives. Current budget: `pnpm format:check` ≈ 30 s, `pnpm lint` ≈ 30–88 s (9 turbo tasks), `pnpm typecheck` ≈ 17–35 s, `pnpm test` ≈ 100 s–10 min under load, `pnpm build` ≈ 5–47 s, `pnpm test:e2e` ≈ 2.7–4 min, `pnpm bench` ≈ 3–5 min. Greps that show a result: `pnpm test` → `grep -E "Test Files|Tests |FAIL"`; `pnpm build` → `grep -iE "app.js|gzip|Tizen bundle OK|ERROR"`; `pnpm test:e2e` → `grep -iE "passed|failed|flaky"`; `pnpm bench` → `grep -E "^\[bench\]"`.
- **[gotcha]** A piped `pnpm test 2>&1 | tail -N` is unreliable: sometimes it shows `Test Files` / `Tests`, sometimes the pipe drops them and leaves only Vitest's transform advisories plus `[ELIFECYCLE] Test failed` while the harness records `[exited with code 0]`. Redirect instead — `pnpm test > $SCR/test.txt 2>&1; echo "exit=$?"; grep -nE "FAIL|Tests  |Test Files|AssertionError" $SCR/test.txt` — and never conclude the suite failed from an empty grep.
- **[fix]** `git rebase` aborts with `error: cannot rebase: You have unstaged changes` when the step's work is not yet staged — and chaining `git rebase … && git add …` in one command cannot help, because the rebase runs first. Commit (or stage and stash) before rebasing; skip the rebase entirely when `git log --oneline origin/master -1` equals `git log --oneline -1`.
- **[fix]** Do NOT quote a hand-computed gzip of the Tizen bundle. `node -e "gzipSync(readFileSync('apps/tizen/dist/app.js'))"` printed **397.4 KB** while `pnpm --filter @shmup/tizen build` printed `Tizen bundle OK: app.js 1500.5 KB (386.8 KB gzip of 512.0 KB)` for the same step — `check-bundle.mjs` measures the budgeted payload, the raw file is larger. The figure that goes into `CHANGELOG.md` / `shmup_progress.md` is the one from the `Tizen bundle OK:` line of a fresh build.
- **[pattern]** Edit the long-prose docs (and `shmup_plan.md`) with a python heredoc that asserts the old text first (`assert old in s; s = s.replace(old, new, 1)`) rather than a blind `sed` — the assert is what catches an upstream rewrite or an already-applied edit, and it is the same technique that resolves rebase conflicts in these files. Find conflict markers with `grep -n "^<<<<<<<\|^=======\|^>>>>>>>" <file>`, keep **upstream's** rewritten section, re-apply your edits onto it, and close with `grep -c "<<<<<<<" <file>` (must print 0) plus `npx prettier --check <file>`.
- **[convention]** A plan step's outcome is recorded as an `- **As built:**` block appended directly after that step's `- **Refs:**` line in `shmup_plan.md`, one nested bullet per area, each bullet's bold lead sentence naming the trap and then which test caught it. The same finding is mirrored into `CHANGELOG.md` and `shmup_progress.md` in the same commit. The strongest blocks record **where the implementation deviated from the plan's wording and why** (e.g. "the first cut folded the windows' own p95s instead") and **how a measured number must not be over-read**. Review fixes get their own nested bullet (`(review round 1)`) — do not rewrite the original prose.
- **[convention]** When a recorded/streamed payload gains a new field, keep the reader backward-compatible with sessions recorded before it (fall back to the old computation and mark the printed value, e.g. a trailing `~`, with a footnote) and add a fixture case for the legacy shape — the analyzer tests in `tools/input-probe/test/` carry a `noHist`-style override exactly for this.
- **[pattern]** Verify a statistics change by re-implementing it standalone in a throwaway `node` script under the scratchpad and comparing against the exact answer over synthetic data, rather than trusting the unit tests: M3-02f's pooled percentile was checked by re-coding `fold` + `percentileOf` and diffing pooled vs exact p50/p95 over 20 windows × 180 frames (error stayed within half a quantum, no directional bias), and a worst-case payload was built in the same way (400 windows × saturated histograms = 1.022 MiB against the receiver's 2 MiB cap). A unit test proves the code does what it does; this proves the *quantity* is the one claimed.
- **[convention]** Never claim an on-device millisecond figure is "comparable" with a `pnpm bench` figure. The bench runs Chromium + SwiftShader on a shared desktop; only its **counted** quantities (draw calls, pooled render-target bytes, structure rebuilds, heap delta) and its **in-run ratios** transfer to the TV (`docs/dev/rendering-and-shell.md` § What this bench can and cannot tell you). The correct wording when two figures share a definition is "the same **statistic**, not a comparable **magnitude**" — say which, in every place the number is described.
- **[gotcha]** `tools/input-probe/test/analyzeRender.test.ts` (and its siblings) assert on **exact printed prose substrings** (`expect(report).toContain('…')`). Rewording a report footnote or a docblock that the analyzer prints fails the probe's own `npx vitest run`, which the root gate never covers — grep the probe's tests for the old phrase in the same edit.

- **[gotcha]** Do not poll a background Bash task by `until [ -s <its .output file> ]` from *another* background task — the poller's own output file is also empty until it exits, and a backgrounded `pnpm …` task's `.output` can stay **0 bytes for its whole run**. Redirect yourself: `(pnpm test:e2e > $SCR/e2e.log 2>&1; echo "EXIT=$?" >> $SCR/e2e.log)` in the background, then poll with `until grep -q "^EXIT=" $SCR/e2e.log; do sleep 5; done`. Never fill the wait with `echo ok` no-ops.
- **[gotcha]** Under heavy load (`uptime` ~45, ~50 vitest forks) `pnpm test` reports `[vitest-pool]: Timeout terminating forks worker` and `test/scripts/audio-preview.test.ts` fails at its 60 s limit, and `pnpm test:e2e` can fail two `determinism.spec.ts` cases with `Test timeout of 60000ms exceeded while setting up "page"`. Re-run the single file/spec before treating either as a regression, and never start `pnpm test`, `pnpm test:e2e` and `pnpm bench` concurrently — they starve each other.
- **[gotcha]** `test/bench/zones.perf.ts` "zone I" is the canary of the bench suite: its median sits right at the 1 ms/tick budget and it fails (`expected 1.0573936 to be less than 1`) when `pnpm bench` shares the machine with `pnpm test:e2e`. **Always run `pnpm bench` alone on an idle machine**; re-run it alone before treating a zone tick-budget failure as a regression.
- **[pattern]** A focused Vitest project run from the repo root is `pnpm vitest run --project <shell|core|integration|…> 2>&1 | grep -E "Test Files|Tests |FAIL"`; a focused package run is `npx vitest run --root packages/<pkg> test/<module>` or `pnpm --filter @shmup/<pkg> exec vitest run test/<path>` (≈ 4 s for a single allocation guard). Keep `pnpm test` for the gate.
- **[pattern]** A focused Playwright run is `timeout 600 pnpm exec playwright test --config test/e2e/playwright.config.ts --project=chromium <file-fragment>` (≈ 11 s for one spec) — far faster than `pnpm test:e2e`, which rebuilds both hosts and runs 266 specs in ~3.5 min.
- **[gotcha]** Vitest does not type-check, so a test fixture that goes stale when you add a **required** field to an exported type still passes `pnpm test` and fails only `pnpm typecheck` (`error TS2741: Property 'hist' is missing …`). After widening a shared type in `packages/*/src`, run `pnpm typecheck` before believing a green focused test run — the hand-written sample/fixture factories in `packages/*/test/**` are where it bites.
