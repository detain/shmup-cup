# Campaign runs: the zone map, transitions, the zone tally, bonus stages and the ending hook

How plan step **M2-10** turned the one-zone game into a **run across a branching zone map**
(`shmup_feat.md` §14): the `campaign` content kind (the 9-zone diamond of decision **D9**,
`A → B|C → D|E → F|G → H|I` — five zones per run, 16 routes, two final zones), the **run state**
that carries the players from one zone's World to the next, the zone's **launch intro** (a title
card over the fly-in) and the **stage-clear fly-out**, the **zone result tally** (kill rate, boss
time bonus), the **zone map** screen, the next zone **prepared on the map**, the **hidden
bonus-stage framework** (three kinds of secret entrance, bonus stages, 1UPs and 1,000-point
capsules, the lock-out after a death), the **ending selection hook**, the **practice plumbing**
and eight short **stub zones B–I**, so every route is playable end to end. Since M2-11 zones B and
C are real ([zones-b-and-c.md](zones-b-and-c.md)) and zone B holds the first campaign bonus
entrance; since M2-12 D and E are real too ([zones-d-and-e.md](zones-d-and-e.md)); since M2-13 F
and G ([zones-f-and-g.md](zones-f-and-g.md)), zone G holding the second campaign bonus entrance —
the first `ground` one; since M2-14 the finales H and I are real too, and the ending hook drives
real ending scenes, epilogues and the credits ([zones-h-and-i.md](zones-h-and-i.md#the-endings)) —
no stub zone is left.

## The picture at a glance

```
 title ─ 1 PLAYER / 2 PLAYERS ─ difficulty ─ ship ─ weapons ─┐
   ▲                                                         ▼
   │                         GameScene.enter → FlowControl.beginRun()
   │                           RunState.begin(campaign, stage); prepareStage(zone A)
   │                                                         │
   │    ┌────────────────────── zone World ◄─────────────────┘
   │    │  createRunWorld(run.entry) = runWorldConfig + prepareRunWorld
   │    │  (zone's stage · rank stage term = depth + 1 · players carried in)
   │    │  ZONE X card for 150 ticks over the fly-in
   │    │         │ World.bonus entrance opened ──► 40-tick warp ──► bonus-stage World
   │    │         │                                   (players carried) │ first death:
   │    │         │ ◄── 60 ticks, back at the entrance, entrances locked ─┘
   │    │         ▼ status stageClear → ships fly out (PlayerState 'leaving')
   │    │  StageClearScene (zone mode): tallyZone + awardZoneBonus,
   │    │  noteWorldEnd, captureCarry → run.carry            (a bonus stage's clear
   │    │         │                                            is the zone's clear)
   │    │   ┌─────┴──────────────┬──────────────────┐
   │    │   ▼ exits              ▼ final zone       ▼ practice
   │    │  MapScene             ending chosen,     title
   │    │  Up/Down, OK:         run recorded       (nothing recorded)
   │    │  PrepareStage(next)   EndingScene ──► title (prepareStage(start) again)
   │    │  LAUNCH 60 ticks
   │    └── advanceZone(next): run.carry → run.entry, pendingStart
   │
   └── game over / QUIT TO TITLE (as in M1)
```

Everything above runs on **scene transitions** (a zone clear, a bonus entry, a launch), never
inside a tick. The World itself only gained the fly-out, the enemy totals and the bonus
entrances; everything that spans Worlds lives in `core/scenes`.

## The campaign file (`core/data` `campaign`)

`content/campaign/main.campaign.json` (kind `campaign`, the content naming rule
`<folder>/<name>.<kind>.json`, plus a README and `example.campaign.json`) is **one per content
set** — a second file is an issue and is ignored. `data/campaign.ts` owns it:

| Field | Meaning |
|---|---|
| `id`, `name` (optional, default `ZONE MAP` — the map screen's title), `start` | The first zone of every run |
| `zones[]` | `id` (lower-case kebab), `label` (1–2 upper-case letters / digits — the map node), `name` (≤ 24), `stage` (a stage id: a `normal` or `bossRush` stage, never a `bonus` one), `preview` (0–`MAX_ZONE_PREVIEW_LINES` 3 lines of ≤ 40 characters) — up to `MAX_CAMPAIGN_ZONES` 32 |
| `edges[]` | `{ from, to }` — clearing `from` may lead to `to`; at most `MAX_ZONE_EXITS` 4 exits per zone |
| `endings[]` | `id`, `name`, `zone` (a final zone), optional `all` / `none` — run flags that must be set / clear; up to `MAX_CAMPAIGN_ENDINGS` 32 |

**Graph validation** (`completeCampaign`, collect pass): unique zone ids, a known `start`, edges
between known zones, no self-loops, no duplicate edges, ≤ 4 exits, every zone reachable from the
start, and **every edge leads exactly one depth deeper** (depth = shortest distance from the start,
found breadth-first). That one rule gives the rest for free: no cycles, every route from the start
ends in a **final zone** (a zone without exits), and the map can draw one column per depth.
Endings must name a final zone; every final zone needs one ending **without** conditions (so the
selection always finds one); a flag may not be both in `all` and `none`; ending ids are unique.
Once the references are resolved, `checkCampaignStages` reports a zone whose stage is a bonus
stage. Every problem is reported; the campaign is used only when none was found.

**Derived on load** (`ContentDb.campaign: CampaignSpec | null`): each zone's `stageId`, `depth`,
`row` (its place among the zones of its depth, in file order — 0 is the top of the map), `exits`
(zone indices in edge order) and `final`; the edges' `fromIndex` / `toIndex`; the endings'
`zoneIndex` and bit masks `allMask` / `noneMask`; `startIndex`, `depths` (5 for the diamond) and
`routes` (16, counted with memoisation by `countCampaignRoutes`).

Helpers: `campaignRoutes(campaign)` lists every route (zone indices, depth-first in exit order —
allocates; tests and playtests use it), `campaignZoneIndex(campaign, id)`, `runFlagMask(names)`,
and the **ending hook** `selectCampaignEnding(campaign, zone, flags)`: the first ending of that
final zone (file order) whose `all` bits are all set in `flags` and whose `none` bits are all
clear — `null` only for a zone that is not a final zone of a valid campaign.

**Run flags** (`RUN_FLAG_NAMES`, bit `i` = `1 << i`, `core/scenes` `RunFlag`):

| Bit | Name | Set when |
|---|---|---|
| 1 | `bossEscaped` | A stage boss escaped when its time limit ran out (`World.endingFlags` — equals `core/bosses` `EndingFlag.BossEscaped`) |
| 2 | `noDeath` | No ship was lost in the whole run (computed at the end) |
| 4 | `noContinue` | No continue was used (computed at the end) |
| 8 | `bonus` | A hidden bonus stage was cleared |

The shipped endings (real since M2-14 — each names a sprite `scene` and an epilogue `text`, and the
campaign's `credits` scroll after them; [zones-h-and-i.md](zones-h-and-i.md#the-endings)): zone H
has *THE CITADEL FALLS SILENT* (`noDeath`) and *THE CITADEL FALLS*; zone I has *THE DEEP IS STILL*
(`noDeath`, not `bossEscaped` — the M2-14 review fix: an escape never earns the ending whose
epilogue sinks the King), *THE FLAGSHIP SLIPS AWAY* (`bossEscaped`) and *THE THRONE IS BROKEN*.

## Campaign run or single-stage run

`createSceneFlow` decides once: when `ContentDb.campaign` exists **and** the host config's
`stage` is the start zone's stage, `SceneFlow.campaign` is the campaign and every game is a
**campaign run**. That is the shipped game — both apps hand the flow `DEFAULT_STAGE_ID`
(`'zone-a'`). Any other stage (the `?stage=` dev stages, open space) gives `campaign === null`:
a **single-stage run** with the M1 stage-clear screen (`TO BE CONTINUED`), exactly as before.
Tests that build a flow on a tiny stage get single-stage runs unless their content has a campaign
starting on that stage.

## The run state (`core/scenes` `run.ts`)

`SceneFlow.run` is one `RunState`, reset by every game start (`begin`):

| Field | Meaning |
|---|---|
| `campaign`, `zone`, `stage` | The campaign (`null` in a single-stage run), the current zone index (-1 there), the stage the World plays |
| `depth`, `route` | Zones cleared before this one (the rank's stage term is `depth + 1`); the zone indices so far, the current last |
| `practice`, `checkpoint`, `pendingStart` | A practice run; the checkpoint the zone starts at (-1 = its start); set by the map and practice so the game scene's `enter` plays the prepared zone instead of starting a new run |
| `entry`, `carry` | Two `CarryState`s: the players when the zone started (RETRY STAGE starts it again from it) and the state travelling to the next World |
| `inBonus`, `bonusStage`, `bonusReturnX`, `bonusLocked` | Inside a bonus stage; its id; the entrance's `x` a failed bonus stage returns to; the zone's entrances locked |
| `flags`, `deaths`, `continues`, `continuesAtStart` | Accumulated run flags (`BossEscaped`, `Bonus`), ships lost and continues used by the Worlds that ended, the continues the current World started with |
| `result`, `ending` | The last zone's `ZoneResult`; the ending picked at the final zone |

`endingFlags` adds `NoDeath` / `NoContinue` to `flags` when `deaths` / `continues` are 0.
`noteWorldEnd(world)` is called whenever a World of the run ends — cleared, left for a bonus
stage, left after one, retried: it adds the World's deaths (`worldDeaths` = the sum of the ships'
`hits`), the continues it used beyond `continuesAtStart`, and its `BossEscaped` ending flag.
`advance(zone)` moves on (route, depth + 1, `entry.copyFrom(carry)`, the bonus state cleared);
`beginPractice(campaign, zone, checkpoint)` starts a one-zone run.

### Carrying the players

Every zone — and every bonus stage, and the way back — is a **fresh World**; the players travel
as a `CarryState` (one `CarriedPlayer` per slot, plus the World's `continuesUsed` and session
hi-score). A class with monomorphic fields; the shield is a private `ShieldState` copy.

- `captureCarry(world, out)` takes: active, lives, score with the continue digit, `continues`,
  `nextExtend`, `extendsEarned`, the loadout (main weapon, Missile, Options, the Direct-mode shot /
  sub levels and family), the speed level, the meter cursor and the shield's lasting state
  (`copyShieldState`: kind, hits, pods, Reduce's scale, the Arm's tier and charge — the i-frames
  and hit / break ticks start fresh). A ship `dying`, `dead` or `respawning` is **down**; a down
  ship with no life left (or `playerOut`) is **out**.
- `applyCarry(world, carry)` (tick 0, stage already positioned) puts it back: an unjoined player 2
  stays inactive; an **out** player gets 0 lives and `dead` at `PLAYER_DEAD_TICKS` — so a World
  where nobody is left is over at once and the continue countdown follows; a **down** player
  respawns blinking and invulnerable (`respawnPlayer`); everyone else flies in (`spawnPlayer`);
  the Options are reset behind the ship. Then the session hi-score, `continuesUsed`, the rank and
  the view are refreshed.

`runWorldConfig(base, run)` is the World's config: `base` (the chosen difficulty, ship, loadout,
co-op — `SceneFlow.gameConfig`) with the current zone's stage, or the bonus stage while inside one.
The first zone (and every single-stage run) keeps the `base` object; any other stage allocates one
config (a transition). Because the whole `base` travels, `stageSkip: 'boss'` (the web app's
`?skip=boss`) starts **every** zone just before its boss.

`prepareRunWorld(world, run, carry)` then sets `world.rankInputs.stage = depth + 1` in a campaign
run, jumps to the bonus entrance a failed bonus stage left from (else to a practice checkpoint),
locks the entrances after such a failure, applies the carry (none: the config's fresh start) and
records `continuesAtStart`. The flow's `createRunWorld(carry)` is exactly
`prepareRunWorld(host.createWorld(runWorldConfig(worldConfig, run)), run, carry)`; the headless
route playtests call the same two functions.

`GameScene.restart(retry)` starts the zone over with `run.entry`: at a run's first zone the entry
is invalid, so RETRY STAGE is a fresh start as in M1; at a later zone it is the state the players
entered that zone with. A retry counts the old World's deaths and continues for the run (a death
before retrying loses `noDeath`), leaves a bonus stage and lifts its lock, and counts a game start
in the save.

## Launch intro and fly-out

**Launch.** A zone's launch is the existing 40-tick fly-in (`entering`) plus a **zone title card**
drawn by `GameScene` for `ZONE_CARD_TICKS` (150) World ticks: a translucent band at screen row 36
with `ZONE B` over the zone's name — `BONUS STAGE` over the bonus stage's name inside one. Only in
campaign runs; the strings are built when the World starts, never while drawing.

**Fly-out.** A new `PlayerState` **`leaving`** (appended to `PLAYER_STATES`, code 5 — hashed as its
index). `core/player` `flyOutPlayer(ship)` switches an active ship to it: out of the player's
control, not banking, no invulnerability blink; `updatePlayer` rides the camera scroll and adds
`LEAVE_ACCELERATION` (0.125) px/tick per tick up to `LEAVE_MAX_SPEED` (8), clamped at
`camera.x + LEAVE_END_X` (the playfield width + 32 — out of view). Only `alive` ships can be hit,
so a leaving ship is unhittable; the weapon system skips its autofire but keeps its Options
trailing. The World starts it in **phase 2** for every active `alive` ship once the status is
`stageClear` — i.e. from the tick after the clear (a ship still flying in leaves after its fly-in).
It only changes ticks after a stage clear, which is why no golden recording changed because of it.
The stage-clear screen opens 90 ticks later over the empty playfield.

## The zone result tally

In a campaign run `StageClearScene` is in **zone mode** (`zoneMode`): entering it

1. tallies the World (`tallyZone(world, run.result, run.inBonus)`): `spawned` / `killed` from the
   new `EnemySystem.stats` (`EnemyStats`: regular enemies spawned — stage events, formations,
   scripts, not bosses —, killed with the credit to a player, and the same two for ground
   enemies; never reset, so a checkpoint restart's re-spawns count again), `killPercent` =
   `floor(100 × min(killed, spawned) / spawned)` (100 without enemies), `killBonus` = percent ×
   `KILL_BONUS_PER_PERCENT` (100); `bossSeconds` / `timeBonus` from the longest fight of a
   **defeated** (dying / dead, not escaped) stage boss — `floor((TIME_BONUS_PAR_TICKS − fight) /
   60) × TIME_BONUS_PER_SECOND` (par 5,400 ticks = 90 s, 100 points per second), 0 over par, and
   `bossSeconds` -1 (`NO BOSS TIME`) without such a boss — a bonus stage, an escape;
2. pays it (`awardZoneBonus`): kill bonus + time bonus to **every player in play** (active, not
   out), then the extends are checked — so a tally can award a ship;
3. `noteWorldEnd`, sets `RunFlag.Bonus` after a bonus stage, and `captureCarry` into `run.carry`;
4. picks where to go: a practice run → the title; the final zone → the ending
   (`selectCampaignEnding(campaign, zone, run.endingFlags)`) and the run is **recorded** now; a zone
   with exits → the map, counting a cleared stage in the save's statistics.

The panel shows `ZONE X CLEAR` (or `BONUS STAGE CLEAR`), the zone's name, the score(s) (`1P` /
`2P` in a co-op game), `KILLS n %`, `KILL BONUS` and `TIME BONUS` (or `NO BOSS TIME`) for
`ZONE_TALLY_TICKS` (300); OK skips. The stage-clear jingle plays as in M1.

## The zone map (`MapScene`, id `map`)

A full screen over the title's drifting starfield. The constructor lays the graph out once: one
column per depth between x 40 and 344, the zones of a depth spread between y 40 and 136 in file
order (`nodeX` / `nodeY`, `Int16Array`s), an 18×12 node box per zone with its label, the edges as
dotted lines (`edgeDots` dots each), and a preview panel (24, 146, 336 × 60) with `ZONE`, the
label, the name and the preview lines of the focused zone. One `ListMenu` per zone over its exits
sorted top to bottom (`exits`), so Up / Down move between them with wrap and the UI kit's
auto-repeat.

- **Look**: the route so far lit (title colour), the zone just cleared yellow, its exits outlined,
  the focused one blinking (16-tick half period), the edge towards it in the focus colour.
- **Input**: Up / Down choose; **OK** pushes `SimEventKind.PrepareStage` for the chosen zone's
  stage (see below) and `LAUNCH` blinks for `MAP_LAUNCH_TICKS` (60); then
  `FlowControl.advanceZone(next)` (the run moves on, `pendingStart`) and `stack.reset(game)` — the
  game scene's `enter` plays the prepared zone. **Back** asks "quit to title?" (`ConfirmDialog`);
  NO reopens the choice. Entering the map fades the music out (there is no `ZoneMap` track yet).
- **A map without campaign** (a flow built on content without one) draws only its title; OK or
  Back goes to the title.
- **Budget**: the flow's UI list grew to **384 commands / 224 string slots** (was 256 / 192). The
  map spends at most `MAP_EDGE_DOT_BUDGET` (160) commands on edge dots: `edgeDots` =
  `clamp(floor(160 / edges), 1, 7)`, so the shipped 14-edge map keeps 7 dots per edge and even a
  32-zone, 128-edge map the validation accepts still fits (the test round found such a map
  dropping 603 commands before this). Its string slots are `8 + 3 + zones`.
- **Zero allocation**: drawing reads the precomputed positions and the content's own strings;
  `scenes-map-alloc.test.ts` guards ticks and redraws.

## Preparing the next zone (`SimEventKind.PrepareStage`)

"The next zone's music and tileset prepared on the map" became a sim event:
`SimEventKind.PrepareStage` (15, `id` = the stage's `ContentDb.stages` index). The flow pushes it
through `FlowControl.prepareStage(stage)`, which remembers the last prepared index
(`preparedStage` — at boot the host config's stage, the one the shell prepares while loading) and
pushes nothing when it did not change. It is called by:

- the map's OK (the chosen zone's stage, while `LAUNCH` blinks);
- `beginRun` (the run's first stage — queued before the new World's stage theme, so a set that is
  already resident switches at once);
- `startPractice` (the practice zone's stage);
- `TitleScene.enter` (the host config's stage again — without it the next run's zone A would play
  through the last zone's set; that was the review round's finding).

`@shmup/shell` answers it with `connectStagePreparation(dispatcher, audio, stages, cuesOf,
onError?)` (wired by `bootShell` with `stageMusicCues`): the audio engine prepares that stage's music
set plus the title theme (`prepareMusic(stage.id, [Title, …cuesOf(stage) without Title])` — a new
list, so a memoised picker's array is never modified). The engine keeps one set resident, so a
`stages`-scoped track of the new stage replaces the old one. A failure goes to `onError` (default:
ignored — the cues stay silent); an unknown index is ignored. **Tilesets need nothing**: every
tile is in the one resident atlas (per-zone texture unloading is M2-17).

## Hidden bonus stages

### Data (`core/data`)

- A stage of **`type: 'bonus'`** (`STAGE_TYPES` gained `bonus`) is a hidden bonus stage: no
  `warning` / `boss` / `bonus` events and at least one `end` (reaching it is its clear).
- A **`bonus` event** (`StageBonusEvent`, appended to `STAGE_EVENT_TYPES` — `StageEventCode.Bonus`
  10) in any other stage is a secret entrance: `stage` (must be a `bonus` stage — checked in the
  reference pass, `checkBonusReferences`), `entrance` (`BONUS_ENTRANCES`: `gap` / `ground` /
  `digit`), `region` (gap — a world rectangle), `digit` 0–9 and `place` (`BONUS_PLACES` 10 …
  100,000, default `DEFAULT_BONUS_PLACE` 100; the last digit is the continue count and is never
  read), `until` (camera x that closes the window — defaults: the region's right edge, `x +
  DEFAULT_BONUS_WINDOW` (600), `x` for a digit, read on arrival), an optional `branch`. At most
  `MAX_BONUS_ENTRANCES` 8 per stage; `until` may not lie before `x`.
- Two content drops (`ENEMY_DROPS`): `oneUp` and `bonusCapsule` (`DropKind` 4 / 5 — the freed
  Options' `FreeOption` moved to 6, content drops first).

### The World side (`core/stage` `bonus.ts`, `World.bonus`)

`createBonusEntrances(host, stats, stage)` compiles the stage's `bonus` events into typed arrays
(`BonusEntrances`: kind, stage id, arm x, `until`, region, digit, place, armed flag, the ground
counters at arming). The World's stage hook calls `arm(eventIndex)` when the runner reaches a
`bonus` event (phase 3); `update()` runs after the runner and the other stage systems (phase 3):

| Entrance | Opens when |
|---|---|
| `gap` | A living (`alive`) active ship's centre is inside the region, while armed |
| `ground` | When the window closes: every ground enemy (a `ground` anchor) spawned since arming was killed by the players, and at least one appeared — counted as totals (`EnemyStats`): the ground kills made **while armed** must reach the ground spawns made while armed, so a kill of a ground enemy of an **earlier** event still up when the window arms counts too (keep none on screen at the window's `x` — M2-13's review finding; the content test holds every shipped stage to it) |
| `digit` | When the window closes: `floor(score / place) mod 10 === digit` for a playing ship (not dying / dead) |

The first entrance to open wins: `entered` / `enteredTick` are set, every entrance disarms, and an
`SFX PowerUpEquip` cue plays at the camera. The World **plays on** — it knows nothing of warps.
`enteredStage()` / `enteredX()` tell the flow where to go and where to come back. `lock()` (a death
in the bonus stage) disarms everything for good. A checkpoint restart calls `clear(runner, x)`:
everything disarms, then the entrances whose `x` lies behind the new camera x and whose window is
still open (and whose branch is taken) re-arm with fresh ground counters; those ahead arm again
when reached. `hashWorld` covers the armed flags, their counters, the entry and the lock
(`mixBonus`, together with `EnemyStats`). Free flight has no stage, so no entrances.

### The flow side (`core/scenes`)

- **Warp.** Outside a bonus stage, while the status is `playing` or `bossWarning`, an opened
  entrance counts `BONUS_WARP_TICKS` (40), then `FlowControl.enterBonus()`: `noteWorldEnd`,
  `captureCarry`, `bonusReturnX = enteredX()`, `inBonus`, and `GameScene.swapWorld` to a World of
  the bonus stage built by `createRunWorld(run.carry)` (players carried; the card reads
  `BONUS STAGE`). An entrance opening after the stage already cleared warps nowhere.
- **Clear.** The bonus World's own stage clear is the zone's clear: the tally reads
  `BONUS STAGE CLEAR`, `RunFlag.Bonus` is set, the zone's boss is skipped and the map (or ending)
  follows. In a single-stage run (`?stage=bonus-range`) the bonus stage's clear is the M1 stage
  clear.
- **Fail.** The first death inside counts `BONUS_FAIL_TICKS` (60 — shorter than a death's dying +
  dead time and than the 90-tick stage-clear delay, so the bonus stage's game over or clear screen
  can never come first), then `failBonus()`: `noteWorldEnd`, `captureCarry` (the dead ship is
  down: it respawns blinking), `leaveBonus(true)` and a World of the zone again —
  `prepareRunWorld` jumps its stage to `bonusReturnX` (`StageRunner.jumpTo`, a checkpoint-style
  restart at that x) and locks its entrances.
- **RETRY STAGE inside** a bonus stage starts the **zone** over from its entry state with the lock
  lifted.

### Items (`core/powerups`)

`oneUp` → `ItemKind.OneUp` (9: `items/1up`, +1 life up to `MAX_LIVES` 9 with the critical
`ExtraLife` cue; at the cap only the pickup sound), `bonusCapsule` → `ItemKind.BonusCapsule` (10:
`items/capsule-bonus`, `BONUS_CAPSULE_SCORE` 1,000 points with the pickup sound). World-space like
the red capsule, in both power-up modes; the sprites are engine sprites from the `items` procedural
generator (the pill in green with a white `+`, and in gold).

## The ending screen (`EndingScene`, id `ending`)

After the final zone's tally. M2-10 built the **result card**: `ENDING`, the ending's name
(`run.ending`, picked when the zone was cleared — `THE END` if none), `ROUTE` with the zones'
labels (`A B D F H`, built in `enter`), the score(s) from `run.carry`, one line per run flag set
(`NO MISS`, `NO CONTINUE`, `BONUS STAGE CLEARED`, `A BOSS ESCAPED`) and `THANK YOU FOR PLAYING`.
OK after `ENDING_LOCK_TICKS` (60, then `OK: CREDITS` — or `OK: TITLE` without credits — appears)
or `ENDING_TIMEOUT_TICKS` (1,200 = 20 s) moves on.

M2-14 put a **story** before the card — the ending's sprite scene (`citadel` / `abyss`, with a dawn
for a flawless run and the flagship sailing off after an escape) and its epilogue line by line —
and the **credits** (`CreditsScene`) after it, both to the final zone's `music.ending` /
`music.credits` themes. An ending without scene and text (the example campaign) still opens on the
card. The whole story: [zones-h-and-i.md](zones-h-and-i.md#the-ending-screen-endingscene-id-ending).

## Practice plumbing

`SceneFlow.startPractice(zoneId, checkpoint = -1, loadout = null)` (the loadout since M2-15) starts a practice run of one zone of the
content's campaign (even when the flow is not in campaign mode) at a checkpoint of its stage, with
the next game's config: the zone's rank stage term (`depth + 1`), a fresh start (no carry). It
returns `false` without a campaign, for an unknown zone or an out-of-range / non-integer checkpoint.
On success the stage is prepared, a game start is counted and the stack resets to the game. The
clear's tally returns to the title (M2-15: through `finishGame()` — the name entry when the score
entered its table).

**M2-15** put the **practice select** on it (PRACTICE on the mode select: ZONE, CHECKPOINT,
LOADOUT, START → the difficulty / ship / weapon select; `FlowControl.launchGame()` starts the run
with `RunState.loadout`, which `runWorldConfig` applies) and gave practice **its own tables**:
`recordRun` records a practice run into `hiScoreModeKey(config, 'practice')` (`meter-normal-practice`
…) with the name entry, counts no `gameOvers` / `stagesCleared`, and a practice World plays against
that table's best and never raises the session hi-score — see
[front-end-and-attract.md](front-end-and-attract.md#the-practice-select).

## Saves and hi-scores

- A campaign run is recorded **once**: when its final zone is cleared (before the ending) or on its
  game over — `reached` is the World's stage id (e.g. `zone-h`). A zone cleared on the way to the
  map only counts `stagesCleared` (and flushes the save).
- Single-stage runs record at their stage clear, as in M1.
- Practice records into its own tables since M2-15 (`…-practice`, no statistic) — before, it
  recorded nothing. RETRY STAGE and QUIT TO TITLE still record nothing.
- Since M2-15 every recorded row goes through the name entry and the hi-score table screen, whose
  zone column shows the campaign label of the stage reached (`H`, `I` …).

## Determinism, hashing and golden replays

- Nothing new in the sim uses the RNG; the fly-out is plain arithmetic on the camera.
- `hashWorld` covers the bonus entrances and `EnemyStats`; the new drop codes, the `leaving` state
  and `StageEventCode.Bonus` are appended, never renumbered — except `DropKind.FreeOption` (4 → 6),
  which is never content and never saved.
- **Re-blessed** (`10b5fea`): the hash layout grew, the two new engine sprites shift the sorted
  sprite ids and `bonus.enemies.json` shifts zone A's enemy spec indices; every zone A scenario kept
  its inputs, tick count and outcome. `captain-range-god`, `raid-range-god` and `twin-range-god`
  were re-recorded with the improved bot (it now faces the first *fighting* boss slot — it used to
  look at slot 0 only and never found a double boss's survivor in slot 1): same outcomes, shorter
  fights. The test round added `bonus-range-god` (the ground entrance), `bonus-range-digit` and
  `bonus-vault-god` (capsules and the 1UP) without changing any older file
  ([debug-and-replays.md](debug-and-replays.md#golden-replays-testgolden)).
- A replay covers **one World** from its config: a later campaign zone (players carried in, a
  rank stage term above 1) cannot be rebuilt from a replay header. Goldens record single stages;
  the route playtests rebuild each zone with `prepareRunWorld` instead.

## Zero allocation and the hot-path rules

- `BonusEntrances.update` / `arm` read typed arrays only; `clear` and `lock` are cold paths.
  `stage-bonus-alloc.test.ts` flies a long stage with all three kinds armed.
- The fly-out is three additions per ship per tick.
- `EnemyStats` is a class of four numbers, incremented in place.
- The map, the tally and the ending draw from strings built at scene entry (`enter`) or owned by
  the content; `MapScene.tick` and `drawUi` never build one (`scenes-map-alloc.test.ts`).
- Everything that allocates — `captureCarry` / `applyCarry`, `runWorldConfig` for another stage,
  the new World — happens on a scene transition.

## Using it headlessly

```ts
import {
  RunState,
  createWorld,
  prepareRunWorld,
  runWorldConfig,
  stepWorld,
  tallyZone,
  awardZoneBonus,
  captureCarry,
  createInputSnapshot,
  selectCampaignEnding,
} from '@shmup/core';

const campaign = db.campaign!; // loadContent(files).db
const input = createInputSnapshot(); // a bot fills it every tick
const run = new RunState();
run.begin(campaign, null);
for (;;) {
  const world = prepareRunWorld(createWorld(runWorldConfig(config, run), db), run, run.entry);
  while (world.status !== 'stageClear' && world.status !== 'gameOver') stepWorld(world, input);
  tallyZone(world, run.result);
  awardZoneBonus(world, run.result);
  run.noteWorldEnd(world);
  captureCarry(world, run.carry);
  const zone = campaign.zones[run.zone];
  if (zone.final) {
    console.log(selectCampaignEnding(campaign, run.zone, run.endingFlags)?.name);
    break;
  }
  run.advance(zone.exits[0]); // the top exit
}
```

`test/playtest/campaign.ts` is this loop with a bot at the controls (`playRunZone` plays one zone,
`walkCampaignRoutes` the route tree — every prefix played once: 31 zone runs for the 16 routes,
`cloneRun` copies the run state at each fork). With the real flow:
`createGame(platform, { stage: 'zone-a', stageSkip: 'boss' }, db, { scenes: 'game' })`, then drive
the menus with action presses; `game.scenes.run` / `.map` / `.ending` expose the state
(`test/integration/campaign-flow.test.ts`).

## Extending it

| To add | Do this |
|---|---|
| A zone | A stage file, a `zones` entry (label, name, preview) and its edges in `main.campaign.json`; keep every edge one depth deeper and ≤ 4 exits; a new final zone needs an unconditional ending |
| An ending | An `endings` entry for a final zone; put flagged endings **before** the unconditional one (the first match wins) |
| A run flag | Append to `RUN_FLAG_NAMES` and `RunFlag` (bit order), set it in `RunState` (`noteWorldEnd` or the tally), add its line to the ending's `ENDING_FLAG_LABELS`; old campaign files stay valid |
| A bonus entrance in a zone | A `bonus` event in the zone's stage naming a `type: 'bonus'` stage; for a `gap`, mark the region with terrain or blocks; `pnpm content:check` validates it |
| An entrance kind | Append to `BONUS_ENTRANCES` and `BonusEntrance`, give `checkBonusEvent` its required fields and default `until`, and test it in `BonusEntrances.update` (typed arrays only) and `hashWorld` if it has state |
| A bonus item | A content drop (`ENEMY_DROPS` + `DropKind`, content drops first), an `ItemKind` (append), its row in the item table and its collect path in `core/powerups`, an engine sprite in a generator |
| Something else to prepare between zones | Handle `SimEventKind.PrepareStage` in the shell (`dispatcher.on`), keep it a background task that never blocks the flow |
| Another way into practice (a boss-rush pick, a stage select) | Fill `FlowControl.practice` (zone, checkpoint, loadout, `active`) and let the chain's last OK call `launchGame()`, or call `SceneFlow.startPractice(zone, checkpoint, loadout)` directly; the practice table and the isolation follow from `run.practice` (M2-15) |

## Gotchas

| Symptom | Cause / fix |
|---|---|
| A `?stage=` game shows `TO BE CONTINUED`, never the map | By design: only a game on the campaign's start zone's stage is a campaign run |
| Content fails with "must lead one level deeper" | An edge skips a depth or goes back: depth is the **shortest** distance from the start, so a shortcut edge to a deeper zone changes that zone's depth. Keep the map layered |
| A final zone is reported without an unconditional ending | Every final zone needs one ending with neither `all` nor `none` (the selection must always find one) |
| The wrong ending is chosen | Endings are tried in file order — put the flagged ones first |
| A later zone's music is silent | The stage's cues were not prepared: the flow pushes `PrepareStage` only through `FlowControl.prepareStage`; a new way into a stage must call it too. A bonus warp sends none — a bonus stage's own `stages`-scoped track would not be resident (its cues resolve through the zone's set) |
| The next run's zone A plays the last zone's theme | A flow path that returns to a game without passing the title or `beginRun` skipped `prepareStage` (the review round's bug) |
| A test counting drop codes sees `FreeOption` as 6 | M2-10 appended `oneUp` / `bonusCapsule` as content drops 4 / 5 |
| A test that runs zone A to `stageClear` sees the ships move afterwards | The fly-out: from the tick after the clear every `alive` ship is `leaving` |
| The zone tally shows `NO BOSS TIME` after a boss | The boss escaped (no time bonus), or it was a bonus stage (the boss was skipped) |
| A new scene throws `RangeError` about string slots | The UI list has 256 string slots since M2-14 (224 in M2-10 — the map needs `11 + zones`, the ending its epilogue lines, the credits 24) |
| An entrance never opens after a death in its bonus stage | By design: the lock-out. RETRY STAGE lifts it |
| A `ground` entrance opens with one of its targets still standing | A ground enemy of an earlier event was still up when the window armed and was shot in its place (the window compares totals). Keep ground enemies off screen at the window's `x` — `content.test.ts` plays every shipped `ground` stage and checks it (M2-13: zone G's turret moved from x 2,000 to 1,830) |
| A `gap` entrance does not open with a ship in the gap | Only an `alive` ship counts (not one flying in, respawning or dying) and only while the camera is between `x` and `until` |
