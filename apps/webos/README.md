# `@shmup/webos` — the LG webOS TV app

The same game as [`@shmup/tizen`](../tizen/README.md), packaged for **LG webOS 5+** instead of
Samsung Tizen. Plan step **M3-03**; `shmup_tech.md` §3.3 ("Extra platforms this buys almost free —
LG webOS, same model, `.ipk`, new adapter ≈ 1 day").

> ## Never run on hardware
>
> The project has **no LG TV, no LG developer account and no webOS SDK**. Everything here was
> written from LG's published web-app contract and is verified only by unit tests with fakes:
> `ares-package`, `ares-install` and `ares-launch` have never been executed, and no build of this
> app has ever been loaded on a device. The on-device checks are the owner's — plan §8.7. Treat the
> first real run as untested code, not as a regression.

## What differs from the Tizen app

| | `@shmup/tizen` | `@shmup/webos` |
|---|---|---|
| Manifest | `public/config.xml` (widget) | `public/appinfo.json` |
| Package | `.wgt` via `tizen package` | `.ipk` via `ares-package` |
| `Platform.id` | `tizen` | `webos` |
| Back key | **10009** | **461** |
| Play/Pause | 10252 | 415 (and 19) |
| Key registration | `tizen.tvinputdevice.registerKeyBatch` | none — webOS delivers every remote key |
| Exit | `tizen.application.getCurrentApplication().exit()` | `webOS.platformBack()`, else `window.close()` |
| Input profile | `tizen-remote-safe` | `webos-remote-safe` (`content/input/webos.input-profiles.json`) |
| Device line | `webapis.productinfo` model + firmware | none (nothing verifiable) |
| Live reload | `tizen:watch` | — |

Everything else — the renderer, the audio engine, the scene flow, the save format, the atlas, the
content — is the shared `@shmup/shell` boot and the same packages. A profile's `hosts` list
(`@shmup/input-web`) keeps each TV's remote profile out of the other's CONTROLS menu, so a Tizen
player can never pick the profile whose Back is 461.

## Engine floor

webOS 5 runs Chromium 68 — one release older than Tizen 5.5's 69. The build therefore uses the
**same** `chrome69` + `es2018` target, the same `.browserslistrc` floor and the same hand-written
`globalThis` polyfill (read straight out of `apps/tizen/polyfills/`, so the two cannot drift).
webOS 4 is Chromium 53 and is **not** a target: nothing here was written for it.

## Commands

```sh
pnpm --filter @shmup/webos dev        # Vite dev server on :5175 (works in a desktop browser)
pnpm --filter @shmup/webos build      # dist/ + scripts/check-bundle.mjs
pnpm --filter @shmup/webos test
pnpm --filter @shmup/webos typecheck
pnpm --filter @shmup/webos lint

# Never run from here (no SDK, no device) — documented for the owner:
pnpm --filter @shmup/webos webos:package   # ares-package dist -o release
WEBOS_DEVICE=<name> pnpm --filter @shmup/webos webos:install
WEBOS_DEVICE=<name> pnpm --filter @shmup/webos webos:run
```

`build` produces `dist/`: `index.html`, one classic IIFE `app.js`, `appinfo.json`, `icon.png`,
`largeIcon.png` and the atlas pages under `assets/atlas/`. `scripts/check-bundle.mjs` enforces the
same budgets as the Tizen widget (imported from its check, so there is one source of truth):
`app.js` ≤ 512 KB gzipped, atlas pages ≤ 2048², `dist/` ≤ 8 MB.

## Layout

| Path | What |
|---|---|
| `src/main.ts` | Entry point: finds the canvas, boots, logs a failure for the Web Inspector |
| `src/boot/index.ts` | Composition root: input, audio, platform, `bootShell` |
| `src/platform/index.ts` | The `Platform` adapter: Back = 461, lifecycle, exit, storage |
| `public/appinfo.json` | The webOS manifest (validated by `scripts/appinfo.mjs`) |
| `public/icon.png`, `public/largeIcon.png` | 80² and 130² icons, generated by `pnpm store:assets` |
| `scripts/check-bundle.mjs` | Post-build check of `dist/` |
| `scripts/webos-*.mjs` | The `ares-*` wrappers — **written, never run** |

See [`docs/dev/platform-polish.md`](../../docs/dev/platform-polish.md) for how the hosts fit
together and [`docs/client/webos.md`](../../docs/client/webos.md) for the owner's side-loading
recipe.
